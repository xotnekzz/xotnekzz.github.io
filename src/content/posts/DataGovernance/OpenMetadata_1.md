# 왜 데이터 카탈로그가 필요했나?

제가 다니고 있는 회사 데이터 팀은  마케팅(UA, MO), CX, 게임 분석 파트 등 모든 부서 업무 도메인별로 데이터 분석환경 열어주어  누구나 데이터 기반 의사결정을 할 수 있는 환경을 구축해 왔습니다.

이를 통해 의사결졍의 속도가 빨랐으며, 실험적인 분석도 누구나 쉽게 할 수 있는 장점이 있었습니다.

**쌓여가는 데이터, 쌓여가는 물음표**

시간이 지나면서 데이터베이스 안에 테이블이 계속 늘어났습니다. 처음에는 몇개 였던 것이 수 십개가 되었습니다. 누군가 분석 목적으로 만든 임시 테이블, 더 이상 분석이 필요하지 않는 테이블, 동일한 지표를 집계하는 비슷한 이름의 테이블들이 뒤섞이게 되었습니다.

문제는 이 모든 테이블들에는 **생애주기**와 **사용량을 측정하는 도구**자체가 없었습니다.  이로 인해 만들어진 날짜는 알 수 있지만, 마지막으로 누가 읽었는지, 지금도 누군가가 사용하고 있는지, 아니면 아무도 안쓰는 유물인 것인지 판단할 수 없어 데이터 베이스는 점점 무거워졌습니다.

**이 테이블, 뭐에 쓰이는 거에요?**

더 근본적인 문제는 컨텍스트의 소멸이었습니다.

어떤 테이블이 왜 만들어졌는지 아는 사람은 그 테이블을 만든 당사자뿐입니다. 인수인계를 잘 했다면 문제가 없겠지만 팀을 떠날때 본인이 만들어낸 수 많은 테이블들을 전부 인수인계를 하는 건 쉽지 않습니다.

슬랙 팀채널에는 아래와 같은 질문들이 반복되었습니다.

>"이 데이터는 어디서 봐야해요?"
>" LTV 지표는 어떤 테이블이 공식일까요?"
>"Retrention 이라는 이름이 붙은 테이블이 세 개인데, 어떤걸 쓰면될까요?"

저희는 메인 업무 이외에 위와 같은 질문을 반복적으로 처리하는데에 시간을 많이 할애 하게 되었습니다.

**속도의 대가**

빠른 데이터 환경을 유지하기 위해 치른 대가는 분명해졌습니다.

- 테이블의 소유자를 알 수 없다.
- 테이블의 사용량을 알 수 없다.
- 같은 이름의 지표가 어떤 테이블 기준인지 알 수 없다.
- 테이블 하나를 삭제했을 때 어디가 깨지는지 확인 하기 어렵다.

단순히 테이블 목록을 보여주는 도구가 아니라, 데이터가 어디서 왔고, 누가 쓰고 있으며, 지금도 유효한지를 팀 전체가 자연스럽게 파악할 수 있는 시스템이 필요해졌습니다. 그리고 이 필요성은 최근 **에이전틱 AI(Agentic AI)의 등장**으로 인해 '있으면 좋은 것'에서 '없으면 안 되는 것'으로 격상되었습니다.

**AI에게도 '지도'가 필요합니다** 

Claude Code, Gemini CLI 같은 도구들이 실무에 자리 잡으며 프롬프트 하나로 쿼리를 짜고 파이프라인을 만드는 시대가 되었습니다. AI는 데이터를 다루는 속도를 비약적으로 높여주지만, 치명적인 약점이 있습니다. 바로 **데이터의 '맥락'을 스스로 판단할 수 없다**는 점입니다.

AI는 테이블 이름과 컬럼 구조만 보고 쿼리를 생성합니다. 그 테이블이 신뢰할 수 있는 공식 지표인지, 아니면 2년 전 누군가 테스트용으로 만든 유물인지 AI는 알지 못합니다. 데이터 카탈로그가 없는 상태에서의 AI 활용은, 잘못된 데이터를 바탕으로 한 '그럴듯한 오답'을 더 빠르게 대량 생산하는 리스크가 됩니다.

결국 데이터 카탈로그 도입은 단순한 자산 정리를 넘어, **AI가 올바른 맥락 안에서 움직일 수 있도록 '신뢰의 기반'을 설계하는 작업**입니다.
